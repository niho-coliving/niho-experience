# 英語原稿のガイドライン

最終更新：2026-10-19（担当3）。旅行者向けの英語原稿を書くときの構成・表現・事実確認の約束。
原稿本文は未公開のうちはこのリポに置かない（[README](README.md)）。

## 原稿の構成

項目名はNIHOappの既存企画ページで公開されている構成に合わせた仮称。正式な項目名は公開API契約（[#7](https://github.com/niho-coliving/niho-experience/issues/7)）で決まる。

| 項目 | 目安 | 書くこと |
| --- | --- | --- |
| title | 60字以内 | 「誰と・何を・どこで」。Kamakuraと体験の名詞を入れる。例：Kamakura Community Dinner with Locals |
| lead | 1〜2文、300字以内 | 体験の情景と、旅行者が得る時間 |
| highlights | 3〜5項目、各90字以内 | 具体的にすること。台帳で確認済みの事実だけ |
| timeline | 3〜5段階 | 時刻（JST）または経過時間と、その段階ですること |
| description | 120〜250語 | 流れ、提供者、場所の雰囲気、誰に向いているか |
| included / notIncluded | 箇条書き | 料金に含むもの・含まないもの。追加料金が出るものは必ず書く |
| notSuitableFor | 箇条書き | 段差、アレルギー、年齢、体力など。理由も短く添える |
| knowBeforeYouGo | 箇条書き | 服装、持ち物、天候、遅刻、写真撮影、言語の程度 |
| hosts | 1人50〜90語 | 提供者本人の回答から書く。掲載名は本人が選ぶ |
| meetingPoint（公開） | 1〜2文 | 駅からの距離、目印。予約後にだけ伝える詳細は分ける |

料金・日時・空席・取消条件は原稿に数字で書き込まず、共通APIの値を画面に表示する（[architecture.md](../architecture.md)）。原稿の本文で触れる場合も、APIの値と食い違わない表現にする。

## 表現の約束

- やさしい英語で書く。短い文、二人称（you）、慣用句を避ける。英語を母語としない旅行者も読む。
- 日本語の用語には短い説明を付ける。例：zazen (seated meditation)、shodo (Japanese calligraphy)。
- 時刻はJSTと分かるようにする。本文では「6 pm」、画面の表は共通APIの値を使う。
- 金額は円（JPY）、単位（per person など）と税込かどうかを明記する。為替換算額を本文に書かない。
- 誰にとって不向きかを隠さない。不向きな人に予約させないことも顧客体験の一部とする。

### 根拠がなければ書かない表現

| 表現 | 理由・条件 |
| --- | --- |
| 特定の人に会える（elderly residents、the head priest など） | 参加者は日によって変わる。提供者が確約できる人だけ書く |
| guaranteed、always、every time | 運営上の例外がある |
| best、only、No.1、most authentic | 比較の根拠がない |
| traditional、historic、local ingredients from 〜 | 由来・産地を提供者が確認したものだけ |
| traditional kintsugi | 漆を使う技法でない場合は書かない。使う材料をそのまま説明する |
| reduce stress、healing などの効果 | 健康上の効果をうたわない |
| exclusive、private | 契約上・運営上その形式で提供する場合だけ |
| Only 2 seats left などの残席 | 共通APIのリアルタイムの値がある場合だけ画面で表示する |
| レビュー・評価・参加者数 | 実在するデータを、収集した場所の規約に従って表示できる場合だけ。OTAのレビューや拠点への評価を、この体験のレビューとして転載しない |

## 事実確認の手順

1. 担当3が[商品台帳](product-ledger.md)の「確認済み」だけを使って下書きを作る。確認待ちの事項は `[CONFIRM: ...]` と明記して残す。
2. 提供者が内容を確認し、`[CONFIRM]` を解消する。安全・資格・保険に関する記述は提供者の回答を記録する。
3. オーナーが販売条件と表現を承認する。承認者と日付は非公開台帳に記録する。
4. 承認された原稿をNIHO共通基盤に登録し、そちらを正本とする。公開サイトは共通APIから表示する。
5. 公開後に内容が変わったら、正本を直し、他チャネル（公式サイト・OTA）の記載も同じ日に揃える。

## 提供者紹介の聞き取り項目

次の5問の回答から紹介文を書く。回答と掲載同意は非公開台帳に保存する。

1. 掲載してよい名前の表記（名前のみ、ニックネームなど）と写真
2. 鎌倉との関わり（住んで何年、どこから来たか、など本人が出してよい範囲）
3. この体験を始めた理由、旅行者に伝えたいこと
4. 体験中に使う言語と、英語でどの程度話せるか
5. 体験の外でのおすすめ（近所の店・場所）。掲載先の許諾が要るものは除く

## SEOとの関係

- 旅行者が実際に使う言葉（cooking class、dinner with locals、zen meditation など）は、内容が一致する場合だけ自然に使う。同じ語の繰り返しや、検索語だけの段落を作らない。
- 購入に役立たない自動生成の記事やページを量産しない。
- 英語以外の版は、人が確認した翻訳がそろってから公開する。
