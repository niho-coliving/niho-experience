# 30日間の流入検証計画

最終更新：2026-10-19（担当3）。対象：[#14](https://github.com/niho-coliving/niho-experience/issues/14)。
検索だけに頼らず、どの導線が確定予約を生むかを小さく確かめる。**この計画は設計であり、営業連絡・SNS投稿・広告出稿・販売条件の変更・本番公開は、それぞれの授権を得るまで実行しない。** 事業者・宿泊施設などへの連絡とSNS等への投稿は、本番運用の開始後にオーナーが行う（2026-10-19のオーナー決定）。担当3は文案と計測の準備までを担う。

## テストサイトで先に確認する範囲

5商品は掲載許可済みで、テスト設定の英語本文・価格・日程・仮素材をmock previewで確認できる。この段階は30日間の販売検証のDay 1に含めない。予約と決済はできず、Umamiへも送らない。参加者からの感想は原稿・導線の改善材料とし、確定予約・売上・検索流入の実績として数えない。P-03・P-04は #19138 の受入前に実販売へ移さない（[登録引き渡し表](../content/registration-handoff.md)）。

## 開始の条件

次がそろった日をDay 1とする。

- [ ] P-01の価格・開催枠・取消・天候・最少催行・販売者がオーナーにより確定している（[商品台帳](../content/product-ledger.md)）
- [ ] 英語原稿と写真が承認され、権利と同意が記録されている
- [ ] 予約先が決まっている。案は2つ：
  - **先行案**：既存のNIHOapp企画ページを予約先にする。niho-experienceの公開を待たずに始められる。流入元の記録方法はNIHOapp側で確認が必要（担当2）
  - **本番案**：niho-experienceの試験販売（連携A）の受入後に、新サイトを予約先にする
- [ ] UTM付きのリンクとQRコードが用意され、合成データで計測を確認済み（[funnel-measurement.md](funnel-measurement.md)）
- [ ] OTAとの在庫同期の手順と担当者が決まっている（[operations.md](../content/operations.md)）

### 守ること

- OTA経由の予約者に、OTAの外で予約するよう勧めない。OTAとの契約の送客・連絡に関する条項はオーナーが確認する。
- レビューは実際の参加者に、各プラットフォームが用意した方法でだけ依頼する。対価を伴う依頼や、関係者による投稿をしない。
- 宿泊施設などへの紹介報酬・割引は販売条件の変更にあたるため、この30日では使わない。
- 宿泊施設や提携先の名前と連絡先は公開文書に書かない（コードで管理し、対応表は非公開台帳）。

## 仮説と判断のルール

数値の基準はオーナーとの合意で確定する仮の値。根拠のある基準値（過去の実績など）が得られたら置き換える。

| 仮説 | 見る指標 | 30日後の判断 |
| --- | --- | --- |
| H1 拠点の接点（館内・SNS・会員の紹介）から予約が生まれる | UTM別の詳細表示・Checkout開始、NIHO全体の確定予約（別集計） | UTM別・体験別の日次visitor合計が100未満なら露出量を見直す。100以上でCheckout開始が少なければ掲示物・原稿を変える。流入元をNIHOの予約へ保存するまでは、予約を個別導線へ帰属させない |
| H2 宿泊施設・地域案内から、泊まっている旅行者の関心が生まれる | 提携先コードごとのQR経由の詳細表示・Checkout開始。確定予約はNIHOで別集計 | 訪問があるのにCheckout開始が少なければ置き方・時間帯・対象を見直す。流入元が予約台帳に記録されるまでは「提携先から予約が生まれた」と断定しない |
| H3 OTAは件数を生むが、手数料と取消を引いた1件あたりの手取りは自社導線より低い | 予約件数、手取り、取消率、予約から開催までの日数 | OTAは止めない。導線ごとの手取りと運営負荷を比べ、次の期間の注力先を決める |
| H4 英語検索は30日では予約に結び付かないが、表示は始まる | ページのインデックス状況、表示回数、検索語 | 30日では停止判断をしない。インデックスされない、意図しない検索語ばかりの場合はページ構成を見直す |
| 運営 | 提供者対応時間、問い合わせ件数、取消理由 | 承認の90パーセンタイルが24時間を超える、または開催当日の連絡漏れがあれば、導線を増やす前に運営を直す |

## 日程

| 時期 | すること | 担当 |
| --- | --- | --- |
| Day -14〜-1 | 開始の条件をそろえる。掲示物・投稿・連絡文の案を作る（送信しない）。提携先の候補を選ぶ基準を決める | オーナー、担当3 |
| 1週目 | A1〜A4を開始（承認後）。毎日、在庫の同期を確認 | NIHO運営 |
| 2週目 | B1〜B3の連絡（授権後）。3〜5か所を目安 | オーナー、NIHO運営 |
| 3週目 | 中間の振り返り。原稿・写真・掲示物の改善 | 担当3 |
| 4週目 | 継続。Day 30で締める | 全員 |
| Day 31 | 判断の記録：導線ごとに続ける／変える／止める。次の30日の案 | 担当3がまとめ、オーナーが決める |

毎週月曜に振り返る。記録の書式：

```text
期間：YYYY-MM-DD〜YYYY-MM-DD（JST）
Umami：体験・UTM別の日次詳細表示／Checkout開始（計測できた訪問のみ）
NIHO：booking_idで一意にした確定予約／確定額／取消・返金（全件。Umamiと個人単位で突合しない）
OTA：管理画面の予約数とNIHO台帳との重複確認
運営：承認までの時間（中央値・90パーセンタイル）、問い合わせ件数、当日の問題
判断と次の作業：
```

公開リポのIssueには判断と理由だけを書き、件数・金額の生データは非公開台帳に置く。

## 担当3が授権なしで進められる作業

- UTMの命名表とQRコードの作成（配布はしない）
- 振り返りの書式と集計の手順
